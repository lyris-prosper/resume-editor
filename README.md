# 拾历 · 拾起经历，呈现实力

面向大学生和应届生的 AI 简历网站。两件核心的事：

- **经历重写**：上传旧简历或经历材料（或从事实库选择），AI 从你做过的事里挖掘能力和价值，每处修改都标出来，由你逐处决定采纳还是保留原文。
- **适配岗位**：粘贴招聘信息，逐条对照要求，按岗位调整表达的角度和重点，再选一套版式生成简历。

事实库是管理经历的地方。AI 只改表达，**不补事实**：数字和成果只能来自你记录过的内容。

## 运行

```bash
npm install
npm run dev      # http://localhost:5180
npm test         # 核心规则的单元测试
npm run build    # 类型检查并构建
```

## 页面与流程

| 页面 | 路径 | 做什么 |
|---|---|---|
| 落地页 | `/` | 首屏文字粒子：先组成“你的无数种可能”，再依次重组成算法架构师、后端开发、产品经理、UI设计、运营 |
| 工作台 | `/app` | 左“适配岗位”、右“经历重写”两个面板。鼠标移入哪侧，哪侧展开；正在输入的一侧不会被收起；触屏点按展开，窄屏上下排列。顶部按进度给出下一步 |
| 导入 | `/app/import` | 上传或粘贴 → 核对拆分结果（分类、机构、时间、每件事都可以直接改，改分类后卡片移到对应分组）→ 保存，并给出下一步 |
| 经历重写 | `/app/rewrite?exp=…&job=…` | 逐件重写，右侧汇总“你的经历体现了”。可以选“通用表达”或按某个岗位重写 |
| 事实库 | `/app/library` | 按教育、实习、工作、科研、项目、校园分栏。栏目可随时改（包括在经历和教育背景之间互转）；内容明显分错时会给出建议 |
| 岗位 | `/app/jobs/:id?step=match/adjust/build` | 三步：对照要求 → 调整表达 → 选版式生成 |
| 简历 | `/app/resumes/:id` | 左侧编辑（每条可 AI 重写）、右侧 A4 预览；八套版式；导出图片和 PDF |
| 聊一段 | `/app/chat` | 和 AI 聊一段经历：接入 DeepSeek 后可以自由讲述，右侧实时整理成机构、时间和一件件事，保存进事实库 |

旧地址（`/app/add?mode=…`、`/library`、`/jobs`、`/studio` 等）会自动跳到新路径。

## 修改标注

AI 重写的结果不是整段替换，而是逐处标注（`src/lib/diff.ts` + `src/components/Diff.tsx`）：

- 没变的字正常显示；删去的变灰并划掉；新写的加粗，并用系统选区一样的浅蓝底标出
- 指向或选中一处修改，两端出现选区把手，上方弹出“采纳 / 保留原文”的深色菜单；键盘回车采纳、退格保留
- 底部可以全部采纳、保留原文，或在此基础上继续编辑
- 挪了位置的词（“对数据进行清洗”→“清洗数据”）合并成一处，避免单独采纳后读不通

## 核心规则（代码里的硬约束）

- 改写里出现事实没有的数字会被拦下或标出（`guard`、`unsupportedNumbers`）
- 本人只是协助的事，不会被写成“主导”
- 同一事件在一份简历里只能用一种表达（`validatePicks`）
- 简历是**快照**：生成时复制文字，之后事实库变化不会影响已生成的简历
- 采纳重写会生成新版本，旧版本在“历史版本”里可以恢复
- 经历标题写作“机构 - 职位（性质）”；全职和栏目本身的性质不重复标注（`src/lib/format.ts`）

## 分类

`src/lib/classify.ts` 先看章节标题（教育背景、实习经历、科研经历……），再看内容线索（学校 + 学历、“实习”、实验室 / 课题 / 论文、学生会 / 社团、竞赛、课程）。“工作经历”标题下的实习、科研、学生组织按内容归类。每条都附带识别依据，方便用户纠正。

## 简历版式

| 分组 | 版式 | 说明 |
|---|---|---|
| 一页简洁 | 简洁标准、页眉色带、衬线雅致、现代留白、双栏名片 | 前三套对应设计参考图；衬线雅致和双栏名片可放证件照 |
| 履历丰富 | 大厂高密度、紧凑专业、学术科研 | 大厂高密度参考 [vibe-resume](https://github.com/LiuMengxuan04/vibe-resume) 的高密度技术简历：教育写进抬头、经历用色带标题、要点加粗 |

内容较多时自动推荐“履历丰富”一组（`contentVolume`）。

## 接入 DeepSeek

**在项目根目录的 `.env.local` 里填密钥**（已经建好，照着 `.env.example` 写）：

```
DEEPSEEK_API_KEY=sk-你的密钥
DEEPSEEK_MODEL=deepseek-flash      # 可选：deepseek-v4-pro 更强、更慢
DEEPSEEK_REASONING=none            # 可选：none 最快；low / high 会先思考
```

保存后不用重启，页面顶栏会从“本地规则”变成“DeepSeek”。密钥只在本地服务端使用：浏览器请求 `/api/ai/*`，由 `server/aiPlugin.ts`（挂在 Vite 开发服务器和 `vite preview` 上）带上密钥转发给 DeepSeek，不会进入前端代码。`.env.local` 已在 `.gitignore` 里。

| 任务 | 用 DeepSeek 做什么 | 提示词 |
|---|---|---|
| 经历重写 / 按岗位调整 | STAR + XYZ 结构、强动词、量化维度、挖掘能力；按岗位换说法、调重点 | `REWRITE_SYSTEM` |
| 和 AI 聊一段 | 把对话加工成结构化事实（可拆成多件事），同时起草简历表达，并追问结果和数字 | `INTERVIEW_SYSTEM` |
| 导入简历 | 拆分并按标题和语义分类，保留原文 | `PARSE_RESUME_SYSTEM` |
| 识别岗位 | 拆出职责、核心要求、门槛和加分项 | `PARSE_JOB_SYSTEM` |

提示词都在 `server/prompts.ts`，参考了 [resume-bullet-writer / resume-quantifier](https://github.com/paramchoudhary/resumeskills)、[Resume-Matcher](https://github.com/srbhr/Resume-Matcher) 的真实性规则，按中文校招简历改写。要求与经历的对应仍在本地计算（快、可解释）。

**量化而不编造**：模型只能用事实里的数字；需要数字但没有时写成【补充：受访人数】这样的占位，页面上显示为橙色虚线框，用户填入真实数字后会同时记进这件事的事实。模型如果仍写出了来源里没有的数字，`scrubNumbers()` 会把它换成占位并说明原因。简历编辑器顶部会提示还有几处没填。

没有配置密钥、余额不足或网络出错时，自动改用本地规则（`src/lib/ai/mock.ts`），页面底部会说明原因。正式部署时，把 `server/aiPlugin.ts` 里的处理函数搬到任意服务端（如 Serverless 函数）即可，前端不用改。

## 数据

资料只保存在当前浏览器的 IndexedDB 里，顶栏“本机保存”可以备份、恢复 JSON、载入演示资料或清空。旧版本的数据会自动迁移（`src/store/migrate.ts`）：原来的“工作 / 项目”两类按性质拆到新栏目，确认状态去掉，其他内容不变。演示资料（林知夏、星野科技等）都是虚构的。真实简历样本请放在 `samples/real/`（已加入 gitignore）。

## 设计语言

- **白纸黑字**：纯白底、近黑墨色，三档灰表示层级，细线分隔
- **衬线为骨**：Source Serif 4 + 思源宋体，日期和计数用齐线等宽数字
- **两种颜色**：选区蓝只表示“AI 新写的文字”；提醒橙只表示“与事实不符”。按钮一律黑白
- **层次**：首页面板和图标底座有轻微立体感，下一步提示和浮动工具条用毛玻璃
- 落地页和工作台共用同一套字体、颜色、按钮和顶栏；品牌图标在 `public/brand/`
- 简历模板有自己的字体（多数用思源黑体），因为它们是交给招聘方看的文件
