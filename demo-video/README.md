# 「拾历」Demo 视频 · 交接说明（给接手合成的 cloud session）

本目录（仓库 `demo-video-assets` 分支的 `demo-video/`）是本地会话留下的**真实网页实操素材**。分支其余部分与 `main` 相同，可以直接 `npm install && npm run dev` 运行产品；`tools/` 里的脚本写的是本机路径，仅供参考。所有用到 DeepSeek 的环节（导入拆分、AI 重写、补数后再生成、岗位解析）都已经在本机用真实模型跑过并录好；接手方只需要做剪辑、动效包装、配乐和导出，**不需要也不应该重新调用 AI**（云端没有 DeepSeek 密钥，产品会退回本地规则，结果会不一样）。

原始需求全文见 `BRIEF.md`。用户后来追加的要求：

1. 演示简历改用用户提供的附件（虚构人物「陈知远」，见 `assets/`），目标岗位是**字节跳动 · 后端开发实习生**，JD 由我们自拟（`assets/jd.txt`，末尾注明“演示用示例岗位描述，非字节跳动官方招聘信息”）。
2. 最后生成的简历要**满满当当**——已做到：一页 A4，内容铺到约 94% 高度（见 `final/resume-export.png`）。
3. 动画、合成等后续工作交给 cloud session。

## 录制方式与真实性说明（请在交付说明里如实保留）

- 所有点击、滚动、输入都是发给真实页面的输入事件（CDP `Input.dispatch*`），页面状态、AI 结果全部来自运行中的产品副本（未修改源码）。
- **光标是录制时注入页面的一个小图层**，跟随真实鼠标事件移动，按下时有一圈浅灰涟漪；因此素材里自带光标，不需要后期再画（如需后期光标，`mouse` 轨迹可用）。
- **PDF 拖入**：操作系统层面的拖放无法自动化，脚本向投放区派发了真实的 `dragover` / `drop` 事件，文件由页面自己用 pdf.js 读出文字。拖动过程中光标旁的「陈知远_简历.pdf」文件卡片是录制时叠加的示意，不是产品界面。
- **演示 PDF**：用户附件的文字层是碎片化的，产品读出来会夹杂空格（如“校园高并 发 活 动”）。因此按附件的**同样文字、相近版式**用微软雅黑重新排了一份（`assets/陈知远_简历.pdf`，一页），内容一字未改。
- **第 02 段的取舍**：AI 每次追问的指标不同。脚本读取追问的字段名，只在追问是「吞吐量 / QPS」+「P95」（可再加「异常率」）时才填写，否则整段重录，避免把普通响应时间误写成 P95。最终素材里 AI 追问的三项是：**优化后吞吐量、优化后 P95、异常率**，演示用户依次填入「约 1500 QPS」「约 60 ms」「低于 0.1%」。其余尝试未使用。
- 这三个数字是预先设计的**虚构示例压测记录**，由演示用户手动输入，不是 AI 查证或推断的结果。相关镜头必须标注「虚构示例数据」。建议在 `record-card` 标记处叠加的记录卡文字：
  > 虚构示例数据 · 报名接口压测记录（优化后）
  > 吞吐量　约 1500 QPS　｜　P95 延迟　约 60 ms　｜　异常率　低于 0.1%
- 第 02 段最终采纳的表达（DeepSeek 实际输出）：**高并发报名性能优化**：将报名接口优化至约 1500 QPS、P95 约 60 ms、异常率低于 0.1%：用 Redis 缓存热点活动并设随机过期时间避免击穿，结合查询条件建立联合索引；针对超卖、重复请求和消息重复消费编写测试验证。（原文：性能与可靠性：为热点活动设置缓存和随机过期时间，结合查询条件优化联合索引；针对超卖、重复请求和消息重复消费编写测试，记录吞吐量、P95 延迟及异常率。）
- 岗位 JD 为自拟示例；第 03 段对照要求时，“能用 QPS、P95 延迟说明接口性能”这条要求直接匹配到“性能与可靠性”这件事——匹配是产品在本地按字词计算的。

## 剪辑方案（建议，标记名对应 `footage/seg0N.json` 的 `markers`）

成片布局建议：1920×1080 纸白底（#fff，近黑 #111），录屏放在一个 1600×900 的“窗口”里（左右各留 160px，上 100px、下 80px），顶部留给「步骤标题 + 01–04 进度」，底部留给一条短说明（≤16 字，衬线体，分时出现，不叠在界面上）。推近时在窗口内部做相机缩放，最大约 1.6×（素材是 2 倍像素，推近不糊）；每段先交代整页，再推近，不连续缩放。

| 成片时段 | 素材 | 用哪一段（标记） | 处理 |
|---|---|---|---|
| 14–28s「01 把经历整理成事实」 | seg01 | `start`→`drop`→`text:ready`（拖入、读出文字）；`click:parse`→`review` 之间是 DeepSeek 等待，压到 ≤1 秒；`review`→`scroll:raw`→`hover:project`（左侧原文高亮 ↔ 右侧项目卡片，推近 `rect:project-card`）；`checked`→`click:save`→`saved`（已保存到事实库：教育 1 · 项目 2 · 共 7 件事）；`click:open-library`→`library`（事实库卡片，停 2 秒） | 说明：“导入一次，之后按岗位复用。” |
| 28–53s「02 补充依据，再重写」 | seg02 | `scroll:event`→`original`（原始表达）；`click:rewrite1`→`review1` 等待压缩；`scroll:diff`→`hover:hunk`（蓝色修改标注 + 采纳/保留原文菜单，推近 `rect:card`）约 5 秒；`scroll:quantify`→`record-card` 聚焦橙色待补充（推近 `rect:quantify`）约 4 秒；**在 `record-card` 处叠加虚构示例压测记录卡**，停 2–3 秒让观众看清指标名和数值，再播 `click:qps`→`type:*`（输入可 1.5–2× 加速）约 6 秒；`click:rewrite2`→`review2`（等待压缩）→`scroll:diff2` 展示带数字的新写法约 6 秒；`scroll:facts`（事实里新增“数字”一行，推近 `rect:facts`）；`click:accept`→`final`，最终结果停 ≥3 秒 | 说明分时出现：先“缺少的数字，先补依据。”（待补充/输入时），后“补充的数字，记入事实库。”（`scroll:facts` 时）。输入和结果镜头角标“虚构示例数据” |
| 53–69s「03 同一份经历，对准目标岗位」 | seg03 | `click:jobs-tab`→`paste:jd`（粘贴 JD，停 1.5 秒）；`click:parse-job`→`match`（DeepSeek 等待压缩）→`matched`（整页：有依据/部分相关/待补充统计）；`scroll:req`→`focus:req`（推近 `rect:req-row`：“能用 QPS、P95 延迟说明接口性能” ● 直接匹配 → 校园高并发活动报名系统 · 性能与可靠性，命中 qps、p95、延迟、接口、性能）停 3 秒；`picks`→`click:pick0/1`（用户确认选材，补勾两件事，共 7 件）；`click:adjust`→`expression`（确认采用的表达就是第 02 段的新写法）；`click:build`→`click:tpl-banner`→`click:tpl-classic`（只看 2 套，选定「简洁标准」）；`click:generate`→`studio` | 说明：“按岗位要求，选择有依据的内容。” |
| 69–82s「04 好表达，留下来复用」 | seg04 | `scroll:bullet`→`click:lead`→`type:lead`（左侧把概括从 AI 写的“高并发报名性能优化”改为“报名链路性能与稳定性”）；`preview-updated`（右侧预览同步，推近 `rect:preview-bullet`，可做左右并排）；`click:writeback`→`dialog`（弹窗原文写着“事实本身不会改动，只是多一种写法，以后其他简历也能用。”停 3 秒）；`click:save-variant`→`saved-variant`（写法下拉变成“原文·改”）；`click:style`→`lineheight:set`（「细节」里把行距从 1.55 调到 1.65，内容铺满一页且不溢出到第二页）；`click:export`→`exported`（真实导出图片）；`scroll:paper` 整页；可选 `click:library-tab`→`library-variants`（事实库里这件事出现第二种写法「原文·改」，事实与数字不变） | 说明：“存为新表达，下次写简历继续用。”第二句可用“原事实不变，已生成简历不受影响”。不要写“改一处，处处更新” |
| 82–90s 收束 | `final/resume-export.png` + 前面素材截帧 | 三个节点：事实库（seg02 `final` 帧）→ 岗位表达（seg03 `focus:req` 帧）→ 简历成稿（导出图），回流箭头“好表达，存回库。”，最后「拾历」「拾起经历，呈现实力。」停 ≥3 秒 | |

## 屏幕文案（按需求原文）

- 开场：做过不少事。／简历里，却只剩「负责、参与、协助」。／示例原文“参与校园活动报名系统开发，负责接口优化。”（这是开场的示意句；附件简历本身写得较完整，可改为引用附件原句“性能与可靠性：…记录吞吐量、P95 延迟及异常率。”并在“记录了，但数字呢？”处放大，由接手方决定）／怎么优化？效果如何？／把经历里的依据，写进简历。
- 品牌：拾历／拾起经历，呈现实力。／整理事实 → 对准岗位 → 生成简历
- 步骤标题：01 把经历整理成事实／02 补充依据，再重写／03 同一份经历，对准目标岗位／04 好表达，留下来复用
- 说明：导入一次，之后按岗位复用。／缺少的数字，先补依据。／补充的数字，记入事实库。／按岗位要求，选择有依据的内容。／存为新表达，下次写简历继续用。
- 收束：事实库 → 岗位表达 → 简历成稿／好表达，存回库。
